# Время с пользой

Бот и мини-приложение в MAX для студентов, которые хотят заниматься волонтёрством,
но не знают, какое дело поместится между парами или вечером. Пользователь выбирает
свободное время, получает подходящие смены с учётом дороги, записывается и после участия
получает справку о волонтёрских часах.

[Бот в MAX](https://max.ru/t531_hakaton_max_bot) ·
[Стенд](https://max-bot.centraluniversity.team) ·
[OpenAPI](openapi/openapi.json) · [Проверки API](DATA-API.yaml) · [Презентация](./assets/presentation.pdf)

Проект для трека «Досуг и развлечения» хакатона MAX.

## Для кого и зачем

Студенту приходится искать события в разных чатах, сверять расписание и самостоятельно
считать дорогу. Даже если желание помочь есть, непонятно, успеет ли он вернуться к занятиям.
Координатор организации отдельно собирает заявки, рассылает инструкции и отмечает явку.

Мы объединяем эти действия в одном месте. Студент ищет дело под своё свободное окно,
а координатор публикует смены, видит записи и явку, связывается с участниками через бота.

Команда провела исследование среди примерно 30 первокурсников Центрального университета.
Участникам понравилась возможность проводить свободное время с пользой через волонтёрство;
они выразили желание участвовать в таких делах. Это предварительное подтверждение интереса
к идее. Следующий шаг: проверить, сколько заинтересованных студентов действительно
запишутся и придут на смену.

## Как это работает

1. Студент запускает бота и открывает мини-приложение.
2. При первом входе даёт согласие на обработку данных, выбирает вуз и район.
3. Указывает, сколько времени свободно и когда. Можно загрузить расписание в формате `.ics`.
4. Выбирает дело и записывается. Подбор учитывает продолжительность смены и дорогу туда и обратно.
5. Бот присылает инструкции и напоминания. Из записи можно написать координатору,
   пригласить друга, добавить событие в календарь или передать своё место.
6. На месте студент сканирует QR координатора или вводит шестизначный код.
7. После окончания смены начисляются часы. Справку можно скачать в PDF или получить в чате MAX.

Координатор создаёт смены и короткие онлайн-задания, подтверждает участие, проверяет ответы
и отправляет сообщения записавшимся. Если включён сбор по кворуму, смена состоится только
при заполнении всех заявленных мест к началу; иначе бот сообщит об отмене.

| Команда бота      | Действие                                 |
| ----------------- | ---------------------------------------- |
| `/start`, `/help` | Открыть меню и мини-приложение           |
| `/my`             | Посмотреть ближайшие записи и инструкции |
| `/messages`       | Выбрать смену и написать координатору    |
| `/cancel`         | Завершить текущий диалог с координатором |

## Пилот и развитие

Текущий демонстрационный стенд использует справочники Казани и смоделированные организации
и смены. Исследование в Центральном университете проводилось отдельно от этого демостенда.

Первый реальный пилот планируем провести в Центральном университете: один вуз,
2–3 волонтёрские организации, шесть недель. Для запуска в Москве нужно добавить корпуса
вуза, районы, адреса организаций и реальные смены, назначить координаторов и согласовать
с вузом формат справки. Организации будут поддерживать расписание и подтверждать участие.

На пилоте сравним поиск и запись через привычные чаты с тем же сценарием в MAX.
Будем измерять время до записи, долю записавшихся и пришедших, повторное участие и часы.
Время до записи измеряется на пользовательских сессиях; остальные показатели доступны
в кабинете координатора. Цель пилота: сократить медианное время записи на 30% без снижения
явки. Это целевой показатель, фактический эффект ещё предстоит измерить.

Дальнейший порядок развития:

1. Подключить другие студенческие группы и организации Москвы. Сохраняются подбор, запись,
   отметка и уведомления; добавляются справочники и координаторы. До расширения проверим,
   хватает ли реальных смен на свободные окна студентов.
2. Повторить пилот в Казани, например с КФУ. Нужны договорённости с вузом и местными
   организациями, проверка адресов и времени в пути, согласование учёта часов.
3. После проверки в двух городах добавить разделение данных по городам, настройки часовых
   поясов и транспортный маршрутизатор. При росте нагрузки перенести лимиты запросов
   из памяти одного API в общее хранилище и запускать несколько экземпляров сервиса.

Основные затраты при подключении новой площадки: поиск организаций, проверка их данных,
обучение координаторов и поддержка актуальных смен. Отдельно нужно проверять точность
дороги и принятие справок вузом. Названные площадки являются планом развития, договорённости
о пилотах пока не заявлены.

## Устройство проекта

| Компонент             | Назначение                                                     |
| --------------------- | -------------------------------------------------------------- |
| `app/`                | React, TypeScript, Vite, MAX UI и MAX Bridge                   |
| `backend/app/api/`    | HTTP API на FastAPI, вход и проверка прав                      |
| `backend/app/bot/`    | Webhook MAX, команды и переписка с координаторами              |
| `backend/app/domain/` | Подбор, запись, отметка, часы и справки                        |
| `backend/app/worker/` | Очередь уведомлений, начисление часов, отмены и фоновые задачи |
| `backend/migrations/` | Схема PostgreSQL и миграции Alembic                            |
| `deploy/`             | Caddy                                                          |

Caddy отдаёт интерфейс и проксирует запросы в API. API и worker используют общую PostgreSQL;
там же хранится очередь задач с повторными попытками. Сервис `migrate` применяет миграции,
создаёт ключ подписи справок и при необходимости загружает демо-данные.

Зависимости зафиксированы в `backend/uv.lock` и `app/pnpm-lock.yaml`.
Образы: Python 3.13, Node.js 22, PostgreSQL 16 и Caddy 2.

## Запуск

Нужны Docker и Docker Compose. Перед первым запуском создайте `.env` из `.env.example`.
Если файл уже есть, сохраните его настройки.

```sh
cp .env.example .env
docker compose up -d --build
```

Интерфейс доступен на `http://localhost:8080`. Шаблон окружения включает локальный режим
`APP_ENV=dev`; без токена MAX доступны API и просмотр демо. Для работы в браузере с реальным
локальным API запустите [dev-сервер фронтенда](app/README.md).

| Переменная                        | Значение и назначение                                                                                   |
| --------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `APP_ENV`                         | `dev` для локальной разработки, `prod` для стенда MAX; в Compose по умолчанию `prod`                    |
| `MAX_BOT_TOKEN`                   | Токен выданного бота                                                                                    |
| `MAX_BOT_USERNAME`                | `t531_hakaton_max_bot`, без `@`                                                                         |
| `MAX_WEBHOOK_SECRET`              | Секрет вебхука, 5–256 символов из `A-Z`, `a-z`, `0-9`, `_`, `-`                                         |
| `PUBLIC_BASE_URL`                 | `http://localhost:8080` локально, `https://max-bot.centraluniversity.team` на стенде                    |
| `SITE_ADDRESS`                    | `:80` локально; домен для автоматического TLS через Caddy                                               |
| `WEB_HTTP_BIND`, `WEB_HTTPS_BIND` | По умолчанию `127.0.0.1:8080` и `127.0.0.1:8443`; на сервере `0.0.0.0:80` и `0.0.0.0:443`               |
| `POSTGRES_PASSWORD`               | Локально `vremya`; для сервера задаётся до первого запуска                                              |
| `SEED_DEMO`                       | `true`: загрузить демо при первом запуске; `refresh`: обновлять при запуске миграций; `false`: без демо |
| `TEST_ACCOUNTS`                   | Тестовые доступы в формате `токен:max_user_id` через запятую; каждый токен от 16 символов               |

`SEED_DEMO=true` или `refresh` также включает просмотр демо в интерфейсе.
После смены этого флага нужно пересобрать web. В деморежиме браузера изменения живут
только в текущей вкладке.

На локальной машине web занимает порт 8080, API доступен на `127.0.0.1:8000`,
PostgreSQL на `127.0.0.1:54330`. На публичном стенде внешний доступ идёт через HTTPS.
В режиме `prod` обязательны токен, секрет вебхука и HTTPS-адрес.

Подробности запуска на сервере: [deploy/DEPLOY.md](deploy/DEPLOY.md).
Сервис `bot-setup` регистрирует вебхук после появления HTTPS. Для выданного на хакатоне
бота привязку мини-приложения выполняют организаторы через форму из FAQ.

## Проверка

В MAX используйте два аккаунта: участника и координатора проверенной организации.

1. Откройте бота, пройдите регистрацию, выберите КФУ и район Казани.
2. Найдите дело на подходящее время, запишитесь и проверьте запись в «Моих делах».
3. Пригласите друга и проверьте переход к нужному делу после регистрации.
4. Напишите координатору через бота; ответьте со второго аккаунта.
5. Во время отметки откройте QR в кабинете координатора. Участником отсканируйте его
   или введите код, затем проверьте явку в кабинете.
6. После окончания смены проверьте начисление часов, скачайте PDF и запросите его в чат MAX.

Для проверки API без клиента MAX задайте `TEST_ACCOUNTS`. Роли и запросы описаны
в [DATA-API.yaml](DATA-API.yaml): участник `1`, координатор `900206`, новичок `900102`.
Токены передаются проверяющим отдельно. Запросы используют `Authorization: Bearer <токен>`.

Демо-данные можно обновить командой `docker compose exec api python -m app.cli seed-demo`.
Она сохраняет постоянные id и обновляет даты доступных смен; смены с записями реальных
пользователей не переносятся.

## Разработка и тесты

```sh
docker compose up -d postgres
cd backend
uv sync
uv run pytest
uv run ruff check .
uv run mypy app
```

Тесты создают отдельную базу PostgreSQL и удаляют её после прогона.
Транспорт MAX в тестах заменён на тестовый. Команды сборки и браузерных проверок
описаны в [app/README.md](app/README.md).
